# Confirmed Bugs

This register contains defects supported by current source inspection. It does not treat missing features, unverified security properties, or unresolved product policy as confirmed bugs. No issue below is considered fixed until its acceptance check passes.

| ID | GitHub issue | Priority | Status | Defect and impact | Evidence | Tracker item | Verification criterion |
| --- | --- | --- | --- | --- | --- | --- | --- |
| BUG-001 | [#13](https://github.com/turkananation/pqkeystore/issues/13) | P0 | Open | The public `PqKeystore` constructor names its required parameters `_backend` and `_crypto`, which are private identifiers and cannot be named by callers in other Dart libraries. The documented/tested `backend:` and `crypto:` construction therefore does not match the public API. | [`pq_keystore.dart`](../lib/src/api/pq_keystore.dart), [`README.md`](../README.md), [`memory_backend_test.dart`](../test/memory_backend_test.dart) | TRK-002 | Compile a consumer from outside the library using the documented public constructor; run analysis and package tests. |
| BUG-002 | [#14](https://github.com/turkananation/pqkeystore/issues/14) | P0 | Open | Dart sends `id`/`data` in channel calls, while Android and Apple handlers expect `key`/`value`. Core put/get calls therefore fail argument validation. | [`platform_keystore_backend.dart`](../lib/src/backend/platform_keystore_backend.dart), Android and Apple plugin sources | TRK-006, TRK-007 | Shared contract tests exercise put/get/delete/contains/metadata against each native handler. |
| BUG-003 | [#15](https://github.com/turkananation/pqkeystore/issues/15) | P0 | Open | Dart expects a boolean result from native `delete`, but current Android and Apple handlers return no boolean; the client converts a null result to `false`, reporting successful deletion as failure. | [`platform_keystore_backend.dart`](../lib/src/backend/platform_keystore_backend.dart) and native handlers cited above | TRK-006, TRK-007 | Delete an existing item and assert true; delete an absent item and assert the agreed not-found behavior on all platforms. |
| BUG-004 | [#16](https://github.com/turkananation/pqkeystore/issues/16) | P0 | Open | Platform `list()` invokes `listIds`, but Android and Apple handlers do not implement it. Platform listing cannot provide the requested records. | [`platform_keystore_backend.dart`](../lib/src/backend/platform_keystore_backend.dart) and native handlers cited above | TRK-006, TRK-007 | Store multiple items and verify list/filter results on every platform, including empty storage. |
| BUG-005 | [#17](https://github.com/turkananation/pqkeystore/issues/17) | P0 | Open | `use()` supplies the stored `record.aad` to unwrap without checking that it equals canonical AAD regenerated from `record.metadata`. Metadata can therefore be changed while leaving the stored AAD unchanged without this facade detecting the mismatch. | [`pq_keystore.dart`](../lib/src/api/pq_keystore.dart), [`canonical_aad.dart`](../lib/src/crypto/canonical_aad.dart), [`CLAIM_BOUNDARY.md`](CLAIM_BOUNDARY.md) | TRK-003 | Tamper with metadata while preserving AAD and assert unwrap is rejected before plaintext is returned. |

| BUG-007 | [#19](https://github.com/turkananation/pqkeystore/issues/19) | P1 | Open | File replacement deletes the current file before the new temporary file has been written and renamed. A failed write can lose the previously valid record. | [`file_keystore_backend.dart`](../lib/src/backend/file_keystore_backend.dart) | TRK-004 | Inject a write/rename failure and verify the old record remains readable and the index is consistent. |

## Related Capability Gaps

These are tracked as production work rather than confirmed behavioral defects:

- Linux and Windows are registered in package metadata but their plugin sources are stubs. See TRK-007 in [`TRACKER.md`](TRACKER.md).
- `PlatformStoreOptions` are not consistently consumed by native code, and authentication semantics are unresolved. See [ADR-0002](adr/0002-platform-channel-contract.md) and [ADR-0004](adr/0004-unlock-and-secret-lifecycle.md).
- Threshold helper methods enforce basic metadata policy but do not validate threshold parameters or demonstrate an end-to-end `pqthreshold` ceremony. See [ADR-0005](adr/0005-threshold-share-boundary.md) and TRK-008.
